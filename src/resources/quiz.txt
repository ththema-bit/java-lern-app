Code-Quiz. "=== QUIZ" startet eine Frage. richtig: Nummer der richtigen Option (ab 1).
Optionen: Ausgabe in einer Zeile, oder "Kompilierfehler", oder "Exception: Name".

=== QUIZ
id: q01
kategorie: Strings
richtig: 1
--- code
String a = "Java";
String b = "Ja" + "va";
String c = new String("Java");
System.out.println((a == b) + " " + (a == c) + " " + a.equals(c));
--- optionen
true false true
false false true
true true true
false false false
--- erklaerung
`"Ja" + "va"` besteht nur aus Literalen. Der **Compiler** rechnet das schon beim Übersetzen zu `"Java"` zusammen, also landet es im **String-Pool** und ist dasselbe Objekt wie `a` → `true`.

`new String("Java")` erzeugt dagegen immer ein **neues Objekt** → `a == c` ist `false`. Der Inhalt ist gleich → `equals` ist `true`.

**Merke:** Strings immer mit `equals()` vergleichen.

=== QUIZ
id: q02
kategorie: Wrapper
richtig: 3
--- code
Integer x = 127, y = 127;
Integer p = 128, q = 128;
System.out.println((x == y) + " " + (p == q));
--- optionen
true true
false false
true false
false true
--- erklaerung
Java **cacht** `Integer`-Objekte von **-128 bis 127**. Bei Autoboxing von 127 bekommen `x` und `y` dasselbe Objekt → `true`. 128 liegt außerhalb des Caches → zwei verschiedene Objekte → `false`.

**Merke:** Wrapper-Objekte (`Integer`, `Long` ...) immer mit `equals()` vergleichen!

=== QUIZ
id: q03
kategorie: Operatoren
richtig: 2
--- code
int i = 5;
int j = i++ + ++i;
System.out.println(i + " " + j);
--- optionen
7 11
7 12
6 11
6 12
--- erklaerung
- `i++` (Post-Inkrement): liefert den **alten** Wert 5, danach ist `i` = 6.
- `++i` (Prä-Inkrement): erhöht **zuerst** auf 7 und liefert 7.
- `j` = 5 + 7 = **12**, `i` = **7**.

=== QUIZ
id: q04
kategorie: Datentypen
richtig: 2
--- code
System.out.println(5 / 2 * 2.0);
--- optionen
5.0
4.0
4
Kompilierfehler
--- erklaerung
Ausgewertet wird von links nach rechts: `5 / 2` ist eine **Ganzzahl-Division** → `2`. Danach `2 * 2.0` → `4.0` (wegen `2.0` wird es ein double).

Mit `5 / 2.0 * 2` käme `5.0` heraus.

=== QUIZ
id: q05
kategorie: Datentypen
richtig: 2
--- code
System.out.println('a' + 'b' + "c");
--- optionen
abc
195c
ab c
Kompilierfehler
--- erklaerung
`char` ist intern eine **Zahl** (Unicode): `'a'` = 97, `'b'` = 98. Zwei chars mit `+` werden **addiert** → 195. Erst dann kommt der String `"c"` dazu → `"195c"`.

`"c" + 'a' + 'b'` ergäbe dagegen `"cab"`, weil von links nach rechts ab dem String alles verkettet wird.

id: q06
kategorie: Exceptions
richtig: 3
--- code
public class Main {
    static int test() {
        try {
            return 1;
        } finally {
            System.out.print("finally ");
        }
    }

    public static void main(String[] args) {
        System.out.println(test());
    }
}
--- optionen
1
1 finally
finally 1
Kompilierfehler
--- erklaerung
Der `finally`-Block läuft **immer** – auch wenn im `try` ein `return` steht. Der Rückgabewert 1 wird gemerkt, dann läuft `finally` (gibt "finally " aus), danach kehrt die Methode zurück und `main` gibt 1 aus.

id: q07
kategorie: Methoden
richtig: 4
--- code
public class Main {
    static void aendern(StringBuilder sb, String s) {
        sb.append("!");
        s = s + "!";
    }

    public static void main(String[] args) {
        StringBuilder sb = new StringBuilder("Hi");
        String s = "Hi";
        aendern(sb, s);
        System.out.println(sb + " " + s);
    }
}
--- optionen
Hi Hi
Hi! Hi!
Hi Hi!
Hi! Hi
--- erklaerung
Java ist **pass-by-value**: Die Methode bekommt Kopien der Referenzen.
- `sb.append("!")` verändert das **Objekt**, auf das beide Referenzen zeigen → sichtbar.
- `s = s + "!"` erzeugt einen **neuen** String und biegt nur die lokale Kopie um → außen nicht sichtbar.

id: q08
kategorie: Vererbung
richtig: 2
--- code
public class Main {
    public static void main(String[] args) {
        Tier t = new Hund();
        System.out.println(t.name() + " " + t.art());
    }
}

class Tier {
    String name() { return "Tier"; }
    static String art() { return "TierArt"; }
}

class Hund extends Tier {
    @Override
    String name() { return "Hund"; }
    static String art() { return "HundArt"; }
}
--- optionen
Hund HundArt
Hund TierArt
Tier TierArt
Kompilierfehler
--- erklaerung
`name()` ist eine Instanzmethode → **Overriding**, entschieden zur Laufzeit nach dem echten Objekt → `Hund`.

`art()` ist **static** → kann nicht überschrieben, nur **verdeckt** (hiding) werden. Entschieden wird beim Kompilieren nach dem **Variablentyp** `Tier` → `TierArt`.

id: q09
kategorie: Collections
richtig: 1
--- code
List<Integer> list = new ArrayList<>(List.of(1, 2, 3));
list.remove(1);
System.out.println(list);
--- optionen
[1, 3]
[2, 3]
[1, 2]
Exception: IndexOutOfBoundsException
--- erklaerung
`remove(1)` mit einem `int` ruft `remove(int index)` auf → entfernt das Element an **Index 1** (die 2).

id: q10
kategorie: Collections
richtig: 3
--- code
List<String> l = List.of("a", "b");
l.add("c");
System.out.println(l);
--- optionen
[a, b, c]
[a, b]
Exception: UnsupportedOperationException
Kompilierfehler
--- erklaerung

id: q11
kategorie: Kontrollfluss
richtig: 2
--- code
int x = 2;
switch (x) {
    case 1: System.out.print("eins ");
    case 2: System.out.print("zwei ");
    case 3: System.out.print("drei ");
    default: System.out.print("default");
}
System.out.println();
--- optionen
zwei
zwei drei default
zwei default
eins zwei drei default
--- erklaerung
Beim klassischen `switch` mit `:` gibt es **Fall-Through**: Ohne `break` läuft die Ausführung ab dem passenden `case` einfach in alle folgenden weiter.

Der moderne switch mit `->` hat dieses Problem nicht.

id: q12
kategorie: Operatoren
richtig: 2
--- code
int a = 0;
if (a != 0 && 10 / a > 1) {
    System.out.println("A");
} else {
    System.out.println("B " + a);
}
--- optionen
A
B 0
Exception: ArithmeticException
Kompilierfehler
--- erklaerung
`&&` ist **short-circuit**: Ist die linke Seite `false`, wird die rechte gar nicht ausgewertet. Die Division durch 0 passiert also nie.

System.out.println(0.1 + 0.2 == 0.3);
--- optionen
true

id: q14
kategorie: equals & hashCode
richtig: 3
--- code
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Set<Punkt> s = new HashSet<>();
        s.add(new Punkt(1, 2));
        s.add(new Punkt(1, 2));
        System.out.println(s.size());
    }
}

class Punkt {
    int x, y;
    Punkt(int x, int y) { this.x = x; this.y = y; }
}
--- optionen
1
0
2
Exception: ClassCastException
--- erklaerung
`Punkt` überschreibt weder `equals` noch `hashCode`. Dann gilt die Version aus `Object`: Zwei Objekte sind nur gleich, wenn es **dasselbe** Objekt ist. Also landen beide im Set → 2.

Mit korrekt überschriebenem `equals` + `hashCode` (oder als `record Punkt(int x, int y)`) wäre es 1.

Integer i = null;
int j = i;
System.out.println(j);
--- optionen
0
null

id: q24
kategorie: Exceptions
richtig: 1
--- code
public class Main {
    public static void main(String[] args) {
        try {
            Object o = "Text";
            Integer i = (Integer) o;
            System.out.println("A");
        } catch (ClassCastException e) {
            System.out.println("B");
        } finally {
            System.out.println("C");
        }
    }
}
--- optionen
B C
A C
B
Kompilierfehler
--- erklaerung
Der Cast kompiliert, weil `o` vom Typ `Object` ist – es *könnte* ja ein Integer sein. Zur Laufzeit ist es aber ein String → `ClassCastException` → "B". Danach läuft `finally` → "C".

Sicher casten: `if (o instanceof Integer i) { ... }`
